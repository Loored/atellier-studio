3. **Current evidence.** Advertise only registered, role/budget-allowed bounded reads and carry current run evidence with QA/repair outcomes. 4. **Independent quality gate.** Separate format, provenance, goal fidelity, safety, and cost. Build a protected evaluator whose criteria cannot be edited by the variant under test, a reserved varied-goal holdout, versioned rubric, immutable evidence, and a manual calibration sample. Default unknown semantic quality to unverified; never turn speed alone into `improving`. **Exit:** historical four formal false positives are rejected by an independent audit; repeat the frozen matrix unchanged, then a previously reserved holdout. This slice is not complete merely because operator criteria reach QA.
5. **Learning record.** Group repeated failures by exact reason, source, role, version, and evidence digest. Record hypotheses, successful/failed variants, contradictions, expiry, and graph links. Keep all generated conclusions context-only until promotion meets the policy. **Exit:** a later run demonstrably uses a specific proven lesson, while an invalidated lesson stops influencing context.
6. **Local experiment coordinator.** Bounded queue derives one hypothesis at a time, generates a fingerprinted configuration variant, evaluates baseline/variant with equivalent contexts, and stops or retains evidence. First variable classes: context selection, retrieval/tool choice, bounded repair, and model profile; no arbitrary code execution. Enforce a serial Ollama budget and user-work priority. **Exit:** automatically completes one useful and one rejected experiment with matching provenance, no hand-entered observation labels.
7. **Bounded adoption/rollback.** Separate durable operator authorization for each narrowly reversible configuration class and maximum sample/cost. Only protected quality improvement plus no safety regression can trigger shadow → sampled canary → adoption. A regression, loss of evidence, expiry, or process restart causes automatic fail-closed rollback. **Exit:** demonstrate a selected improvement and a rollback with exact immutable receipts, while pending human review/irreversible effects remain human-controlled.
8. **Code and meta-improvement.** Agent may propose a one-file limited patch in a disposable worktree. Immutable protected tests/metrics must execute outside the candidate's editable tree with secrets, network, and commands isolated. Human approves initial code integrations. Subsequently study whether changing the proposal/selection strategy improves holdout outcomes across generations. **Exit:** trace lineage and generalization, not just same-case scores; no automatic primary-checkout merge without a separately authorized, proven policy.

## Authorization and sequencing

Automatic now: bounded reads, candidate analysis and discard, local mocks. Not authorized now: autonomous trusted-memory promotion, Control Bundle activation from receipt-only quality, document writes without their existing approval, code merges, network actions, or changes to protected evaluation. Human interventions should ultimately be policy setup, ambiguous goals, exceptions, and irreversible final effects—not every internal experiment. Expand authority only after the preceding exit check actually passes.
